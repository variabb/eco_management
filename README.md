# Комп'ютерний еко-енергетичний менеджмент — ЛР №1 і №2

**Навчальний проєкт** на Python, Streamlit і SQLite для умовного енергомоніторингу кінотеатру «Планета Кіно — Блокбастер».

> **Увага:** всі 10-річні споживання, ціни, площі, температури, витрати, обсяги послуг, умовні СЕС та CO₂ є синтетичними навчальними даними. Вони не являють собою фактичну інформацію про кінотеатр.

## Швидкий запуск у PyCharm

1. Відкрийте папку як Python-проєкт; налаштуйте інтерпретатор (Python 3.10+).
2. Створіть віртуальне середовище, якщо ще немає:
   `python3 -m venv .venv` і `source .venv/bin/activate` (macOS).
3. Встановіть пакети: `python -m pip install -r requirements.txt`.
4. Запустіть: `python -m streamlit run app.py`.
5. У лівому меню оберіть **«📐 Енергетичні індикатори (ЛР №2)»**.
6. Оберіть рік, підрозділ і ресурс; перемикайте вкладки для розрахунків.

До архіву включено вже наповнену **`energy.db`**. Старі дані лабораторної №1 залишилися без змін.

## Файли

- `app.py` — головна програма Streamlit, всі вкладки ЛР №1 та ЛР №2;
- `database.py` — основна схема SQLite (ЛР №1);
- `energy_data.py` — генерація вихідних даних (ЛР №1);
- `lab2_data.py` — нові таблиці та моделювання показників ЛР №2;
- `indicators.py` — формули індикаторів;
- `lab2_page.py` — сторінка ЛР №2 із таблицями, розрахунками й формами;
- `test_lab2.py` — автоматичні тести;
- `export_lab2.py` — експорт CSV у `exports/`;
- `energy.db` — підготовлена модельна SQLite-база з даними за 2016–2025 рр.

## Корисні команди

```bash
python test_lab2.py
python export_lab2.py
python -m streamlit run app.py
```

## Принципи розрахунків

- Середньодобове: `обсяг / робочі_дні` за умови `робочі_дні > 0` і `обсяг > 0`.
- Середньодобове «за рік»: середнє середньодобових лише за активні місяці.
- Нерівномірність: `max(середньодобові) / min(додатні середньодобові)`.
- Питоме опалення: `Гкал / м²`; модельне освітлення й кондиціювання `кВт·год / м²`.
- Енергетична складова: `витрати на електроенергію та теплову енергію / усі операційні витрати × 100%`.
- Власна генерація: `власна генерація / (власна генерація + придбана електроенергія) × 100%`.
- Енергоємність послуг: `(електроенергія + теплова енергія × 1162,22 + власна генерація) / виручка × 1000` кВт·год екв./тис. грн.
- Викиди: `0,40 × кВт·год придбаної електроенергії + 230 × Гкал тепла`, кг CO₂ (задані умовні коефіцієнти).
- Питомі викиди: `кг CO₂ / виручка, грн × 1000`.
- Градусо-дні: `max(0, 15,5 - Тзовн) × робочі дні`.

Виручку змодельовано лише для підрозділу «Кінозали», тому для інших підрозділів показники на 1000 грн послуг не визначаються. Модельний сценарій власної сонячної генерації з'являється лише з 2023 року в адміністративно-технічній зоні — це **не твердження про реальну СЕС**.

## Технічні примітки

SQLite у Streamlit Community Cloud може втратити внесені користувачем зміни після перезапуску контейнера. Для захисту лабораторної використовуйте локальний PyCharm або завантажте результати CSV. `populate_lab2_model()` не дублює записи й не перезаписує існуючі ручні поля.
